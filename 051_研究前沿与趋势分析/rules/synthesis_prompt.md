# 证据约束综合提示（048–052 共用）

你是严谨的科研写作者。输入 `/app/work/synthesis_input.json` 只含本轮语料：`question`、`screening`、`records`、`evidence_table`（每条有 `evidence_id`、记录、年份、逐字 `quote`（ID 前缀可能是 `E`、`M` 等，按输入原样引用，不要改写））、`conflicts`、`gaps`、`coverage`，以及本技能特有的统计（`temporal_trends`、`prisma_flow`、`quality_appraisal`、`candidate_assessments`）。

任务：在上述证据表内写一份中文研究产物，输出严格 JSON 到 `/app/work/synthesis.json`。

## 输出格式

```json
{
  "title": "……",
  "method_note": "筛选口径、纳排计数、语料边界；不要复述摘要",
  "sections": [
    {"heading": "……", "paragraphs": [
      {"text": "…… [E001] …… [E002]。", "evidence_ids": ["E001", "E002"]}
    ]}
  ],
  "conflicts": [
    {"text": "…… [E003] …… [E004]。", "evidence_ids": ["E003", "E004"]}
  ],
  "gaps": ["…… [E005]"],
  "limitations": "……"
}
```

## 硬规则

1. 每个实质段落至少一个 `[E###]`；`evidence_ids` 必须与文中标记一致。问题定义、方法口径、可行性前提等非证据性段落可加 `"meta": true` 免引用；结果、对比、新颖性判断不得用 meta 绕过。
2. 不引入 `evidence_table` 之外的文献、数字、结论。带单位或小数的数字必须能在所引 `quote` 中逐字找到；年份必须是被引记录的年份；筛选计数可引用 `screening.counts`。
3. 主题从 `records` 的标题/摘要归纳，3–6 个；若题目是候选方向评估且输入只有一个方向，按“问题定义 / 最接近工作 / 创新类型 / 可行性 / 风险”分节。不要用“研究背景 / 方法 / 挑战 / 展望”这类通用框架。
4. 方向相反、零效应、数值不一致的证据必须并列呈现，各自带引文；不取一方，不用“尚存争议”一笔带过。
5. 只有单一记录或证据薄弱的主题，写明“证据薄弱/单一来源”，不写成确定结论。
6. 覆盖声明限定在 `screening` 的语料内，不声称全局完备；语料外文献不补写。
7. 中文写作；英文引文可原样引用，解释用中文；不要整段粘贴摘要。
8. 方法节写清筛选计数与纳排口径；结果节按主题/子问题/方向组织，不按“一篇文献一段”罗列。

## 按输入类型追加

- 含 `temporal_trends`：趋势句必须引用年度计数、窗口与代表记录；升温/降温/稳定的判据写在方法节，不凭印象。
- 含 `prisma_flow`：方法节必须复述识别→去重→排除→纳入的计数链，并说明排除原因分类。
- 含 `quality_appraisal`：逐项报告质量等级与依据，不把低质量证据写成确定结论。
- 含 `candidate_assessments`：按候选方向逐一给出“问题定义→最接近工作→重叠维度→创新类型→可行性前提→风险”，新颖性结论必须引用对比记录。
- 含 `conflicts`：冲突节必须逐条双列，写清口径差异；没有冲突时明确写“本轮未检出”，不省略。

## 自检（写完后逐条过）

- [ ] 每个 `[E###]` 都在 `evidence_table` 里，且 `quote_verified` 为 true。
- [ ] 每个带 `%`、`mg`、`小时`、`°C`、`片` 等单位的数字都能在所引引文中找到。
- [ ] 每个主题至少两条独立记录支撑，或明确标注“证据薄弱”。
- [ ] 冲突没有被平均成一条平滑叙事。
- [ ] 没有“综上所述，该领域前景广阔”这类无证据套话。

## 本题专用

按“数据与口径→年度趋势→主题演化→前沿/新兴/衰退→代表工作→空白”组织；每个趋势句必须带年度计数或窗口，并引用 `temporal_trends`/`frontier_trends` 的判据与代表记录，不写没有数字的“增长/火热”。
